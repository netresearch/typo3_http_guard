# Independent TYPO3 source review

Reviewer: policy-module agent; extension production code was implemented by a different agent. This is a source review and regression-evidence review, not the original G6 requirement for another human person.

The review covered deployed configuration, event registration and diagnostic failure handling, global middleware order, cloning/rebinding the Core stack, fixed Core context restrictions, endpoint/PublicFetch wrappers, command output, mode transparency, service creation and the newly added raw RequestFactory ABI boundary. Existing middleware and Core restrictions remain in the actual stack; diagnostic bootstrap failures install an explicit denial middleware and are not allowed to create an open HTTP path. Registry/context/stack assertion closures retain object ownership across the wrappers.

Required findings and disposition:

1. `policy-check` constructed PSR-7 before raw syntax validation and lost empty fragments. The integration agent reproduced this on actual TYPO3 14/Guzzle 8, then moved `assertRawUri` before request construction. Focused unit and extended real command matrices cover it. The new version-specific RequestFactory boundary applies the same raw check to Core string calls; standard already-parsed PSR-18 information loss is separately documented.
2. Overdue `reviewAfter` fields never appeared in diagnostics. Doctor and config-check now return configured profile IDs in an offline warning list using the injected clock. Review dates remain warnings rather than grant expiry.
3. Doctor's previous capability expression could claim protection while curl-multi was disabled or the Promise/PSR-7 tuple differed. It now invokes shared `RuntimeSupport::assertSupported` and reports an unsupported result; the real matrix includes a disabled `curl_multi_exec` subprocess.
4. Doctor's previous proxy inventory omitted NO_PROXY and mixed-case names. It now uses the shared process-environment inventory and prints names only, with secret values redacted.
5. The default DNS backend parsed OS configuration during unused service construction, preventing disabled/static-only startup on missing resolver files. The library now reads default OS nameservers at first DNS query, with immediate validation retained for explicit injection. A red/green policy regression covers the missing-file seam.
6. The new raw RequestFactory initially validated only enforce calls. Its final source now reports a would-deny diagnostic for invalid raw strings in observe before PSR-7 erases them, then delegates to the exact original Core factory. Disabled remains silent. The focused regression is green in the 19-test/73-assertion unit suite, and the final source-bound matrix proves the corresponding original Core delegation.

The earlier 124-run matrix is superseded by the delivered final matrix: 168 processes, 140 wire assertions, 152 offline CLI processes and four ordinary conflict-startup denials. I inspected its PASS summary, README component mappings and execution hash record, which reports unchanged production/fixture/lock/Core source and exit0 throughout the run. It additionally starts with a real flat legacy Vault allowlist entry and proves the public path still denies private access in all four cells. All six findings have implementation and regression evidence; no unresolved defect remains from this review. This closes this cross-agent source review, while G6 still requires the separately specified human reviewer. No production source was edited by this review agent in the TYPO3 extension.
