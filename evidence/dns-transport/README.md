# DNS and capability transport evidence

Both dependency majors pass the final independent DNS transport suite: **9 tests / 189 assertions each**, PHP 8.5.10, pinned image `ghcr.io/typo3/core-testing-php85@sha256:53df750b7e68ccce8da03a03bfe7cb57d732308b932f2ea92b1fd31679626bc6`. `runtime.json` records the actual Guzzle/Promises/PSR-7 and libcurl versions. `source-sha256.txt` binds the production source, rule data and independent fixture bytes; no production change was needed for these tests.

The fixture runs with `--network host --add-host nss-only-guard.test:10.23.4.12`. It uses the actual registry and `StaticThenDnsResolver` with injected controlled DNS answers, the production terminal/transport, and independently observed TCP/HTTP counters on all three owned targets. It tests NXDOMAIN/SERVFAIL packet rejection, empty/incomplete/malformed responses, a private CNAME destination, CNAME cycles and hop/address limits, NSS-only negative lookup, and policy reauthorization of a memo hit. Every rejection records native-handle and target counter witnesses. The memo test rebuilds the registry as required by immutable snapshot deployment; it does not claim live revocation of a retained old client.

The real cURL optionset failure probe injects `curl_setopt(CURLOPT_RESOLVE)` returning false in an isolated Guzzle handler namespace: one native handle is attempted, no TCP or HTTP contact occurs, and no active lease remains. The unknown dependency probe unregisters Composer's loader metadata before `InstalledVersions::reload`; the actual visible version is `9.99.99` and the production send rejects with `transport_unsupported` before native construction. A child with the actual `curl_multi_exec` function disabled likewise rejects before native or wire contact.

T044 receives an actual HTTP `Proxy` header in an owned PHP CLI server. `getallheaders()` observes it; this SAPI sanitizes `$_SERVER['HTTP_PROXY']` to absence. Process-local proxy names stay empty. The subsequent guarded request preserves `guard.test:8090`, contacts public-a once and makes no new connection/request to either alternate target. The observed SAPI behavior is recorded, rather than forcing a fabricated server variable.

The **genuinely missing curl** probe is separate because both the testing image and the fetched official PHP image compile curl statically: `-n` does not remove it. `missing-curl/` passes on actual host PHP **8.5.11**, using `-n -d extension=ctype` for Guzzle 8's required port parser while curl and curl-multi remain absent. Both majors return `transport_unsupported`, construct zero native handles and leave all parent TCP/HTTP counters unchanged. The child cannot read cURL counters and explicitly records `parent_only`; the curl-capable parent supplies the actual target witnesses. The portable runner is `tests/Integration/Fixtures/run-missing-curl.py` and records its exact command.
