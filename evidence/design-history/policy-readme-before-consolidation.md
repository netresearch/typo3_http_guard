# Policy, configuration and DNS contract

The framework-free policy module uses `Netresearch\HttpGuard`. `GuardConfig::fromArray()` validates the original v1 schema and fills its defaults: enforce mode, no endpoint grants, five-second positive DNS memoization, 32 memoized hosts, 64 addresses and eight CNAME hops. Unknown fields, wrong types, noncanonical CIDRs and invalid calendar dates fail with `configuration_invalid`. Endpoint permissions require a purpose, owner, exact origin, methods and narrow networks; loopback additionally requires the flag and an exact /32 or /128. IPv4-mapped IPv6 CIDRs are rejected in configuration; mapped address candidates are classified and matched as their embedded IPv4 address.

The configuration revision includes the SHA-256 of normalized configuration and the bundled `data/security-corpus/address-rules.json`. Construct a new registry, resolver and engine when deploying changed configuration or address data. Existing contexts belong to their original registry and cannot be used with the new registry. Instances are immutable snapshots; there is no file watcher or automatic in-place policy reload.

`TargetNormalizer::normalize(RequestInterface)` checks the available URI representation and Host header, then returns the canonical request, origin and optional literal address. It preserves the request body, path, query and credentials. `assertRawUri(string)` must run before constructing a PSR-7 URI when an integration receives raw URI text. A PSR-7 implementation can discard information such as an empty fragment (`https://example.test/#`) or normalize syntax before the guard receives it. Standard PSR-18 requests cannot recover that discarded text; the raw-input seam rejects it where the integration still has it. The 33 raw URI fixtures exercise this seam explicitly.

`PolicyRegistry::newContext(?string $endpointId)` issues a scope and, for an explicitly selected configured endpoint, an opaque grant. Contexts, scopes, grants and connection plans are bound by object identity. Grants cannot be cloned or serialized; constructed copies and contexts from another registry are rejected. This protects integration boundaries against accidental reuse; it is not a sandbox against arbitrary PHP execution. Endpoint selection belongs in trusted service wiring, never in a user-controlled request field.

`PolicyEngine::plan()` validates target, method, endpoint origin and every resolved address. An operator deny or hard-denied class wins over an endpoint grant. One forbidden candidate blocks the whole attempt; private answers are never filtered away to keep public ones. Metadata and platform addresses have no generic endpoint exception. Public IPv6 requires a bundled IANA allocation and must pass special-range classification. `assertCurrent()` repeats registry, revision and expiry checks immediately before transfer without another DNS lookup. A plan has no authority outside its owning context. `evaluate()` returns a diagnostic decision and one redacted event; `hostAllowed()` is a host/address preflight and creates no send capability.

`StaticThenDnsResolver` uses an exact configured static host or A, AAAA and CNAME queries for the absolute name ending in a root dot. It validates the complete owner chain, family, record fields, TTL, cycles and configured limits. Unrelated owners and authority/additional records never become target candidates. CNAME plus address data for one owner, conflicting aliases, incomplete answers, empty usable answers, a ninth hop or a 65th distinct address fail closed. Static hosts supply addresses and do not themselves grant permission.

Positive memoization uses a bounded FIFO and the minimum remaining TTL across the used chain, capped by the configured maximum of five seconds. Time spent on later queries cannot extend earlier TTLs. TTL-zero and negative answers are not cached. Every memo hit is still classified and authorized against its request context; the cache contains no allow decision or grant.

`WireDnsQuery` is the default trusted backend. It accepts at most three numeric nameservers from `/etc/resolv.conf`; no NSS, hosts, search suffix, mDNS, HTTP or native-resolver fallback is used. The default OS configuration is read and validated at the first actual DNS query, so a disabled or static-only path does not require unused DNS configuration. Explicit injected server lists are validated immediately. Connected UDP validates transaction ID, question, flags, response code, compressed names and all record bounds. TC triggers a length-prefixed TCP retry to the same nameserver; an incomplete TCP response is rejected. Only answer-section A/AAAA/CNAME records are returned. The constructor's explicit nameserver/port/timeout injection is a trusted dependency/test seam, not another public configuration schema.

The default deadline is one second per nameserver and query, shared by UDP and its TCP retry. The conservative sequential upper bound is 81 seconds for nine names, three query types and three nameservers; a blackhole at the first unresolved name ordinarily fails after three seconds. This is independent of Guzzle's HTTP timeout and is not an application-wide deadline or a promise of interruptible custom resolvers. A local 50 ms UDP blackhole test verifies the injected backend deadline. Expiry is checked again after resolution. No test sends HTTP to real metadata, administrative or private endpoints.

`DecisionReporter` accepts a closure logger and optional HMAC key. Allowed events default to sampling zero; denied, would-deny and unverifiable events share a per-minute log limit while counters keep every event. Metrics labels are only mode, decision, fixed reason code and configured profile ID. Events contain no request body, query, path, header values, key paths or raw exception. Host is omitted without the configured HMAC-key environment name and injected key, unless the operator explicitly selects plain host logging. Logger exceptions increment a counter and do not change authorization. Policy exceptions expose fixed reason codes and implement the PSR-18 client-exception interface.

Current portable policy evidence is in `../../../evidence/dns-transport/policy-portable-g7.log` and `policy-portable-g8.log`: **41 tests and 1,018 assertions per major**, Guzzle 7.15.5 / 8.2.0, PHP 8.5.10. The real UDP truncation/TCP retry fixture uses a standalone PHP subprocess with ready/completion handshakes, identical UDP/TCP query validation and a length-prefixed response; it needs neither pcntl nor posix. Production source remained unchanged. Earlier PHP 8.5.11 suites (41/1,014), the level-8 static check and benchmark are preserved in `data/security-corpus/evidence/`. The benchmark uses 64 IPv6 addresses, 128 configured profiles and a bound endpoint, without DNS, network or logging: p95 1.455 ms over 200 samples on this WSL host. This is a host measurement, not a declared CI reference-system acceptance result.

`data/security-corpus/policy-coverage.json` maps these policy tests to the original 84 test IDs and states missing transport or integration evidence. `requirements-tests.json` preserves the original baseline ledger; its historical not-run statuses are not release acceptance claims. Unit policy and local DNS tests do not establish HTTP target-counter or SYN-counter outcomes. The original 45 requirements and all 84 scenarios require their separate integration and wire evidence before release acceptance.
