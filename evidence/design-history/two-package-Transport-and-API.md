# Transport and API boundaries

`EndpointClientFactoryInterface`, the PSR-18 public client and `PublicFetchClientInterface` are the supported application-facing APIs. Inject a prebound client into each trusted integration. The framework-free library depends on PSR interfaces, the qualified Guzzle tuple and curl; it reads no TYPO3 configuration or Vault credentials. The adapters supply their own immutable configuration, registry, resolver, clock and reporter.

The SDK binding returned by `GuardedClientFactory::createTransport()` is internal integration infrastructure. Its concrete Guzzle client and progress driver must stay together. Vault uses that pair for ordinary, cancellable and streaming requests; application credential APIs do not return it. A caller-supplied Guzzle request `handler` can replace the stack before middleware entry and is outside coverage. Arbitrary PHP execution, raw sockets, direct curl and unrelated SDK clients are likewise outside this boundary.

The outer boundary validates initial authority, context, options and stack identity. Existing supported SDK middleware remains in place. Every leaf attempt reaches the last terminal, which creates a fresh policy plan. One forbidden DNS candidate rejects the entire attempt. The native attempt is lazy until driver progress, rechecks grant validity after DNS/body preparation, and creates its own CurlMultiHandler and CurlFactory with zero retained easy handles. Each approved hostname gets one complete multi-address CURLOPT_RESOLVE entry. URL authority remains intact for Host, TLS SNI and certificate validation.

Fresh connection, forbid reuse, zero native DNS cache, fixed protocols, no proxy inheritance and no external sharing apply to each native attempt. The hidden CurlFactory rewind retry budget is exhausted so retry and redirect attempts must return through policy. A policy denial revokes the invocation even when a custom retry decider indiscriminately retries. Ordinary network retries receive a fresh plan. There is no unpinned, stream or default-handler fallback after a failed pin or connection.

The response boundary validates Location after custom response middleware and before Guzzle follows it. Generic requests remain same-origin with no downgrade, including preserved-method 307/308 responses; an endpoint may prohibit redirects entirely. Public Fetch uses its own fixed nonsensitive request and may follow permitted public redirects without inheriting credentials. PSR-18 remains no-follow.

Cancellation, terminal failures and callback exceptions release native resources and invocation references. Cancellation during DNS or body preparation prevents native construction; cancellation during an active transfer closes the owned socket. No cross-request pool is retained. `sink` streams the response to the caller's stream or file and does not create another guard-owned body copy. Vault's existing size limits, idle/wall budgets, audit and wiping remain separate.

Raw URL validation must happen before constructing PSR-7 objects. Once a URI creator discards an empty fragment marker or encodes raw syntax, PSR-18 cannot recover it. The TYPO3 raw RequestFactory seam, string diagnostics and opt-in Vault OAuth token endpoint seam validate while the original string still exists. Vault resource APIs receive RequestInterface objects; callers must validate raw resource URLs before creating those requests. The adapter exposes an internal raw-URI helper for that composition boundary.

The address corpus, original requirement/test mapping, tuple locks and real wire witnesses are shipped with the delivery. Extending supported versions, protocols or options requires a source inventory and rerun of applicable P0, wire, integration and mutation cases; Composer resolution by itself creates no new supported tuple.
