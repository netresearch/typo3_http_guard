# Final TYPO3 production integration evidence

Recorded on 2026-10-09. The actual four-cell production matrix passed 168 processes: 140 wire assertions, eight wire runs proving observe/disabled delegation, 152 actual TYPO3 CLI invocations and four ordinary startup denials. Every CLI and startup-denial record showed zero new target TCP accepts and HTTP requests. Unit tests passed 19 tests and 73 assertions. This report concerns the TYPO3 integration; the shared policy, transport, Vault, mutation, dependency security and human acceptance evidence have separate reports.

The final [machine summary](production-matrix-summary.json), [execution source hashes](final-execution-source-hashes.json), [runtime versions](runtime-versions.json), [source and lock hashes](source-and-lock-hashes.txt), [matrix log](matrix-final.log) and [unit log](unit-final.log) bind the recorded result. Individual stdout/stderr files contain each process result and fixed denial reasons. The execution hash record checks that production source, fixture PHP, dependency locks and relevant installed Core/Guzzle source stayed unchanged during the complete matrix. The production manifest also passed strict Composer validation.

The normal response trace is `A.request`, `B.request`, `user.on_headers`, `user.on_stats`, `B.response`, `A.response`. Existing Core Guzzle defaults, its actual allowed-host middleware and project middleware are retained. The stack provider replaces only the two registered own middleware objects, uses the fixed service context and validates the global registry at request time. The root factory validates its source-matched default middleware prefix for Guzzle 7/8.

The raw request decorator validates the exact Core parent ABI and selects a non-readonly shell for Core 13 or readonly shell for Core 14. The final matrix proves DI, `GeneralUtility::makeInstance` and PSR-17 service references are identical, preserves relative PSR-17 construction, and denies conflicting or changed mappings before HTTP. A plain service alias was first tested and failed because Core's provider compilation overwrote it; first/second failure records are retained. Service decoration wraps the real original service after that compilation pass and is used in the final result.

Doctor/config-check also warn about overdue `reviewAfter` profile IDs without denying the profile. The final CLI cases prove the warnings stay offline. Policy uses immutable snapshots: deployment/cache rebuild and controlled worker replacement activate changed configuration. This report does not claim an already-built client dynamically revokes or reloads its old snapshot.

## Wire proof and reproduction

The targets are `http-guard-ext-wire-public` at `203.0.114.102:8080` on internal network `http-guard-g0-probe` and `http-guard-ext-wire-private` at `10.23.5.12:8080` on internal network `http-guard-ext-private`. The public-shaped address is routed only locally; there is no loopback whitelist for the Public profile. The Python image is pinned to `python@sha256:f85c5697265c178cc6887276c55fe16cf3d14ca35c3df6a5eab3b360534a55d2`. Container IDs are U/P. The server counts TCP accepts separately from application HTTP requests and subtracts counter polling. Test values are synthetic.

For denial cases, each individual check records unchanged TCP/HTTP counters. The matrix wraps all offline CLI/startup cases with both target counter snapshots. The shared normative case also inspects the actual owning driver before/after and proves no native handler was constructed; it does not substitute a fake transport. Root's separate transport harness records cancellation socket ends, TLS/mTLS, DNS and IPv6 behavior, which this component matrix does not claim.

Portable reproduction instructions and helpers are in [Build/Fixtures](../../packages/nr-http-guard/Build/Fixtures/README.md). Fresh native Linux fixture directories are recommended. Both Core system and DI caches must be cleared after registration/service wiring changes. The final run used the delivered portable fixture files in fresh prepared native runtimes, rather than only the earlier workspace configuration copies. Local path metadata is refreshed deliberately during preparation; an exact historical lock is retained as evidence, not represented as a portable absolute-path lock.

Three upstream SVG-sanitize advisory IDs are ignored only in disposable fixture manifests: `PKSA-8j6w-3kr7-s9xk`, `PKSA-6j95-1jtb-x6wc`, `PKSA-cbx2-m9db-bmzd`. Reproduction requires an explicit flag to accept that isolated fixture scope. No ignore exists in either production package manifest. No SVG processing occurs in these tests. This is not a passed dependency security gate or permission to deploy those historical dependencies.

## Limits and source references

Early bootstrap calls, direct raw clients/cURL, request-owned Guzzle handler entry before the middleware stack and malicious PHP are outside this global path, as in T077. A preconstructed PSR-7/PSR-18 URI cannot reveal delimiters already erased by its creator; only string entry points can perform the additional raw validation. This component does not claim the full T001–T084 acceptance suite, an automatic Vault retrofit, human security review or a real operator pilot. It has not been published or deployed.

The integration uses the documented [BootCompletedEvent](https://docs.typo3.org/m/typo3/reference-coreapi/14.3/en-us/ApiOverview/Events/Events/Core/Core/BootCompletedEvent.html), [Core outbound HTTP extension point](https://docs.typo3.org/m/typo3/reference-coreapi/14.3/en-us/ExtensionArchitecture/HowTo/RestRequests/Index.html), [Core dependency injection](https://docs.typo3.org/m/typo3/reference-coreapi/14.3/en-us/ApiOverview/DependencyInjection/Index.html), [Symfony service decoration](https://symfony.com/doc/7.4/service_container/decoration.html) and [service closures](https://symfony.com/doc/7.4/service_container/autowiring.html#injecting-service-closures-in-configuration-files). Behavior and parent signatures were verified against the actual locked source, not inferred solely from documentation.
